# PitchIQ V1.3 audit: statistics and probability

Auditor: statistical and probabilistic analyst. Tree: `/home/claude/pitch-caller` @ c602f1c (read only). Scratch scripts:
`/home/claude/audit/stats_scratch/` (probe2-6, bands, regret, pw, nanjs). Fits and the 2026 data are not in this repo, so
every 2025 and 2026 number below is quoted from committed results files, with the file named.

## 1. Verdict

**Grade: D+.** The Step 6 run was done carefully: one shot, locked, leakage-guarded, with a conservative clustered SE. But
it does not prove what the owner will take it to prove. On 2025, a 60-number per-count frequency table reproduces at
least 98% of the college "gain" over raw v1.2. About a third of the D1 gain comes from scoring v1.2 in a harness world it
was never calibrated to, while the core was solved to match that exact world. On 2025 the HS core is worse than plain
per-count frequencies. The calls themselves (zone table, location, pitch choice, traits, learning, temperature) have no
held-out validation and no calibration diagnostics.

- `probe3.py`: correcting the documented Single-A zone bias (heart swing +0.53, off whiff +0.55, way-off whiff +1.53 logit) moves
  the mixes TV 0.02–0.11. D1 3-1 FB 51 → 58%, HS 2-1 FB 69 → 80%. Systematic shifts move calls less than differential (per-cell)
  noise, because choices depend on differences between pitches and spots.
- Side observation (other auditors own this): D1 3-1 empty with an average three-pitch arsenal gives the top call FB middle at
  **51%**, below Drew's 55–70%. This matches the known CI failure.
- `probe4.py` (numerical fuzz), `probe5/6.py` + `nanjs.js` (invalid inputs), `pw.py` (powerRow clamp), `regret.py` (mixing cost),
  `bands.py` (rough band rates).
- Bootstrap code review: three cluster schemes, the largest is used. The two-team pigeonhole is conservative. B = 1000 gives an SE
  of the SE of about 2.2%. Seed 1 is fixed. None of this matters at z ≥ 11.5. Paired differences use the same resamples. `nll`
  clips at 1e-12 without renormalizing, which is harmless because `check_tables` rejects bad tables first.
- Shrinkage (`fit_count.py`): Dirichlet pseudo-count chain (count → base-out → side/late → cell) plus neighbour-level borrowing with
  a per-count level offset (D2 borrows from D1 and D3). This is standard and sound. Traits (`fit_traits.py`): empirical-Bayes
  shrinkage, R = τ²/(τ² + SE²), split-half Spearman-Brown reliability. Sound. HS reliability is 0.2–0.4 at typical samples, and
  the docs say so honestly.

  unknown because `scores.json` is not committed. I infer it is close to the 2025 result (about −0.0004 at college, HS worse) but
  did not measure it.

- Whether af7b441 (scored) equals c602f1c for every frozen file. The clone is shallow. The tip hashes match the pre-go page.
- Whether `PITCH_MP_TABLE` was set in Drew's shell during the run (S9).
- `bands.py` is unweighted by the real pitch mix and compares college/HS to a Single-A truth. It indicates a direction only.
- The perturbation scale σ = 0.1 logit is my assumption about plausible differential zone-cell uncertainty. The tables carry no
  SEs, so I could not size it from the fits.
- The JS engine was probed only for NaN handling, not for full stochastic parity.
