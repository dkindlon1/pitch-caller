## Phase 1

### 1.1 Call-sheet test `callsheet.py`: built, baseline recorded
Files: `callsheet.py`, `callsheet_arsenals.json` (the five sweep arsenals copied from the plan appendix, plus sinker_gb,
low_command and changeup_first built from the same speeds and confidences; see its `_note`), `results/mlb_count_freq.json`.
Decisions Drew made by AskUserQuestion (Nov 6): B2's "secondary" = every allowed pitch type except the situation's
top one; avg_changeup is in B6/B7 with the normal limits (only low_command gets +15).
Implementation choices, recorded here:
- "allowed pitch type" = a pitch type in the root's kept call set (`info["M"]`), i.e. after the confidence cutoff, the
  landing filter, coach rules and the guard(s).
- B8a needs bases-empty states with the same outs, which the grid lacks for runner-on-1st/1-out (full) and runner-on-1st/0
  outs (ci). The tool adds those reference states (full: empty 1 out; ci: empty 0 outs); only B8a and B11 read them.
- B8c needs a runner on 3rd; the landing variants also run at runner on 3rd, 1 out.
- B7's "at least half the non-three-ball situations" = the median of the 9 non-three-ball counts' inside shares >= 3%.
- B5/B7 weights = expected pitches per count. Until 3.8's chain exists: MLB pitch frequency by count from Statcast
  (340,378 pitches; 0-0 25.7%, 1-0 9.7%, 0-1 13.0%, 1-1 10.1%, ...), cached so CI needs no Statcast files.
- Both game states use home=True with `win = e.win_constants(s)` at the PA start (the app's way).
- B1-B3, B5-B7 read the main grid only; variant groups feed their own bands (B8c, B9, B10, B12, B13, T1-T3) and B11.
