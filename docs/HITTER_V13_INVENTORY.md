# v1.3 inventory: shipped numbers from Statcast, the MLB Stats API or MLB-only fits

Plan section 4 / prework Part 0 step 2. Checked against commit `e202169` (branch `feat/hitter-v13-prework`). Line numbers
are at that commit. Nothing was refit or run, except `python app/export_data.py --check`. It reports 3 differences, and all
three are tuple-vs-list artifacts in `V08.TYPED.nongb`, not value changes, so `app/engine_data.json` matches the Python tables.

**How the two engines get their numbers.** Most numbers are literals in `engine.py` with mirror literals in
`app/engine.js`. The rest are files that `engine.py` loads at import (`outcome_params.py`, `spread_params.py`,
`hitter_spread_params.py`, `inplay_typed_params.py`, `run_tables.py`, `college_run_values.json`, `fit_v08.json`,
`sim_constants.json`, `we_tables.json`, `we_rates.json`). JS reads those through `app/engine_data.json`, written by
`app/export_data.py`. "ED key" below means a key in `engine_data.json`. Two generator scripts write both engines' literals:
`profiles_fit.py --write-engines` and `profile_terms_tables.py --write-engines`.

**Levels.** HS, D3 (`college_d3`), D1 (`college_d1`, also used as `college`), MLB. Travel uses HS's tables everywhere
(`engine.py:1957-1959`, `app/engine.js:107`). `RHO_L` = 0.6 at HS / travel and 1.0 elsewhere (`engine.py:59`, ED
`V08.RHO_L`). It scales every term "fitted on MLB hitter behavior". 0.6 is a set value, not a fit.

**Old data.** `data/statcast/sc_<date>.csv` is Savant `details`, regular season, every 4th day Apr 5 to Sep 25, from
`fetch_statcast.py`. It isn't in this checkout. Seasons: 2024 train, 2025 held out, 2026 added for the v1.2 hitter fits.
`data/statcast_minors/A_*.csv` is Single-A 2024-25 (`research_v12/fetch_minors.py`). **New data:**
`C:/dev/pitchiq-data/statcast/{MLB,AAA,A}/<year>/<date>.csv.gz` (only `A/` exists today) and
`C:/dev/pitchiq-data/statsapi/<level>/pitches_<season>.csv.gz`. All the old fit scripts glob the old paths, so each one
needs a loader change first. That is the same change for every row, so the "how to refit" column leaves it out.
